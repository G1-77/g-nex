Key Design Decisions
🟡 Amber clock — not green checkmark on step 4
Green means done. The deposit is not done at step 4 — it is waiting. Using amber and a clock icon sets the right expectation. The user is not confused. They are not anxious. They know exactly what state they are in and what comes next.
✂️ No M-Pesa code field — ever
The only matching signals the admin needs are the phone number (visible on M-Pesa till statement) and the amount. A payment from 0712 345 678 for KES 5,000 is unambiguous. The code was solving an admin problem by creating a user problem. Removed permanently.
🔔 Two notifications — not one
Notification 1 (amber, immediate): "Deposit Under Review" — sent the moment the user submits. Notification 2 (green, after admin confirms): "Deposit Confirmed ✓ — KES 5,000 added." Two notifications gives the user a paper trail and reduces "did it work?" support messages dramatically.
⚡ Phase 2 Daraja STK Push — zero schema change
When M-Pesa STK Push is integrated, only step 1 and step 2 change in the UI. Step 1 becomes "Enter amount → Pay with M-Pesa." Step 2 disappears — Daraja's callback auto-confirms and credits. The deposit_requests table stays identical — the mpesa_reference column that was null in Phase 1 gets populated by the Daraja callback automatically.
